# 豆包接入

当前通过 Spring Boot 直接调用火山引擎方舟 Chat Completions 接口，FastAPI 暂不参与此链路。

## 本机配置

推荐在项目根目录的 VS Code PowerShell 终端运行：

```powershell
.\scripts\start-doubao.ps1 -StartInfrastructure -RestartProjectBackend
```

脚本在同一终端隐藏输入 API Key、读取 model，再启动数据库模式后端。`-StartInfrastructure` 会启动 Docker Compose 中的 PostgreSQL 和 Redis，并等待健康检查；如果基础设施已启动可以省略。`-RestartProjectBackend` 只会停止命令行明确属于本项目路径的 Java 后端，不会自动停止其他程序；8080 被其他程序占用时脚本会直接退出。配置只保存在当前终端及其后端子进程，关闭后需重新输入。不要关闭后端终端。启动完成后在另一个终端启动前端，进入树屋并勾选“使用豆包”。

如果 PostgreSQL/Redis 已经在运行，也可以只执行：

```powershell
.\scripts\start-doubao.ps1
```

若页面显示“豆包待配置”，说明当前运行的后端缺少变量，并不代表密钥被方舟拒绝。修改其他终端的变量不会影响已经运行的 Java 进程。新后端的状态接口会列出缺少的变量名，不返回变量值；调用失败会区分 401 鉴权、403 权限、404 资源、429 限制、超时和回复格式问题。

在火山引擎方舟控制台创建 API Key，并从账号可用模型的 API 示例复制 model 值（模型 ID 或推理接入点 ID）。不要使用豆包消费端的登录凭证，不要把 API Key 放进前端或聊天。

脚本等价的手动流程（不推荐把 API Key 写进命令行历史）是：

```powershell
# 确保 JDK 21 和 Maven 已在 PATH；原 D 盘环境可选运行 scripts/env-d.ps1
$secret = Read-Host '方舟 API Key' -AsSecureString
$env:ARK_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
$env:ARK_MODEL = Read-Host '方舟控制台 API 示例中的 model 值'
mvn -f zhiyu-server/pom.xml -B spring-boot:run
```

手动流程需要先启动 PostgreSQL/Redis，并先停止占用 8080 的旧后端；新环境变量只影响新启动的进程。默认地址为 `https://ark.cn-beijing.volces.com/api/v3`。`.env.example` 只是字段说明，Spring 不会自动加载 `.env` 文件。

打开树屋，单独勾选使用豆包；花园上下文和近期行动反馈各自另行勾选。未配置、未同意或服务失败时明确返回自助引导。状态中的“已配置”仅指变量齐全，不代表账号权限或模型连通已经验证。

## 当前行为

- 服务端校验匿名会话，密钥不进入前端。
- 默认不发送云端；开启后发送当前消息与最近最多 12 条本次对话。
- 花园上下文只由服务端读取当前用户最近三天最多 8 条植物记录和最多 8 个未完成任务；不附认知日记。
- 行动反馈仅在独立授权后发送：当前花园近七天最多 8 条目录内复习行动，仅含 activityId、完成/跳过、帮助评分和难度反馈；不含任务标题、笔记、时间戳或身份字段。未授权时，连发给模型的行动计划也不使用历史反馈。
- 云端和本地共享流程：第一轮先问卡点，后续根据当前表达、时间意愿和允许使用的反馈给出一个行动；拒绝安排时无行动；目录都不适用时继续澄清，不强推。
- 这是工具调用型混合 Agent：豆包负责意图理解、工具选择和自然语言回应；模型可在本地允许的候选范围内提出行动，服务端校验阶段、目录、参数、授权和风险，不把提示词当作唯一限制。
- 手机号、邮箱、身份证号做基础模式脱敏，不保证识别所有个人信息。
- 后端不持久化聊天正文，不记录模型请求正文或供应商错误内容；服务商留存以实际条款为准。
- 输出解析为 JSON，必须返回 phase、reply、needHelp、activityIds。阶段和行动 ID 必须与服务端本轮约束及经工具校验后的选择一致；超出复习目录、多个行动、格式不符或内容检查失败时降级。只有用户点击才能加入任务，未结束同类任务防重复，结束后可主动再添加。
- 规则或模型提示求助时展示固定求助引导，不推荐普通行动；规则有漏报和误报，并非临床风险分类器。
- 连接超时 5 秒、请求超时 25 秒，不自动重试产生额外费用。
- 这是本地开发实现，公开发布前需补限流、费用预算与完整风险评测。

## 工具调用工作流

树屋启用豆包后，后端会同时提供受限的 Function Calling 工具定义。模型可以先查询已授权范围，主动检索知识并按反馈再检索，再查询复习目录，最后提出一个行动；每一步的参数和结果都由本地执行器校验。工具名称和边界如下：

| 工具 | 是否有副作用 | 边界 |
| --- | --- | --- |
| `query_garden_state` | 否 | 只返回本次明确授权的近期花园资料或行动反馈 |
| `search_activities` | 否 | 只返回复习目录中最多三个候选 |
| `search_knowledge_base` | 否 | 检索已审核知识，可按元数据改写查询，最多三次；不放宽用户限制 |
| `propose_action` | 否 | 只能提出检索结果中的一个行动 |
| `create_task` | 是 | 模型调用永远拒绝；只允许用户点击行动卡片后的确认接口 |

页面会显示本轮实际收到的工具调用轨迹（调用名称不等于执行成功）。推荐阶段首轮请求设置 tool_choice=required；服务端进一步要求成功知识检索、检索候选和提出候选行动，缺少步骤则降级。澄清阶段可直接回应。当前实现是方舟兼容的 OpenAI 风格 Function Calling，不是 MCP Server。

2026-10-29 接入轻量 RAG：模型仅能引用本轮检索的已审核条目，引用 ID 由服务端验证。150 条知识块已由 Zz3 逐条审核并写入指纹清单。重启后端后可进行真实模型联合验收；仍需单独启用云端授权，不要把模拟模型测试当作真实豆包质量证据。

## 验证

本轮验证记录见 [复习 Agent 闭环验收](复习Agent闭环验收-2026-10-23.md)。自动测试使用本地模拟供应商，不会调用真实豆包或读取你的密钥；它能验证接口契约、授权隔离、规则约束与降级，不能证明真实模型回答质量、延迟或账号可用性。真人体验时以每条回复中的“豆包生成理解回应”确认该条来自豆包；fallback 是本地引导，调用失败不代表内容一定没有发出。
