# 知愈校园·情绪花园：参赛执行计划

制定日期：2026-10-15。目标截止：2026-10-23，按当天提交预留缓冲，具体截止时刻待确认。资源：单人开发，时间较充裕。本文是实施任务书，勾选项均未表示已实现。

## 1. 定位与评估结论

作品展示名：**知愈校园·情绪花园**。

技术描述：**融合 CBT 自助练习的校园情绪支持交互系统**。保留用户提出的“基于 CBT 的校园情绪花园自助系统”作为方向，但在内容依据和审核完成前，不宣称治疗、疗效验证或临床级风险识别。

核心体验：播种情绪 → 觉察情境与想法 → 选择校园微行动 → 植物成长 → 次日复盘。守园小人物“知知”（暂名）贯穿引导、倾听和行动陪伴。

参赛价值应通过三件可观察的事呈现：植物将情绪记录转成可回访的对象；自助练习和行动与同一株植物关联；复盘留下个人体验变化。花园、AI 记忆、CBT 本身都不是独有创新，创新表述应落在具体组合与验证结果上。

赛道尚未核实。优先核对当届正式指南中与交互应用、数字媒体技术相符的类别；不能把猜测的赛道名称、评审权重或视频时长当成官方要求。10 月 15 日必须核对校内/赛区资格、截止时间、AI 素材要求及提交格式。

## 3. 设计决定

### 花园与角色

- 五个栏目统一为：我的花园、播种情绪、树屋倾诉、任务簿、成长报告。
- 视觉方向：薄荷绿、叶绿、少量土壤暖色的原创手绘花园；中间为真实可交互场景，避免只是给旧卡片换名称。用户要求优先于设计技能的固定色板。
- 六种植物全部保留：小雏菊/平静、向日葵/愉悦、含羞草/焦虑、苔藓/低落、仙人掌/愤怒、蒲公英/迷茫。植物意象是产品约定，不是心理测量或诊断。
- 选择项同时显示植物和情绪名称；不能要求用户猜植物含义，也不能单靠颜色区分。
- 知知必须有可辨识的人物轮廓：头、身体、手脚、园丁帽、固定服装。第一版四状态：欢迎、倾听、陪练、鼓励。求助场景采用平静姿态和清晰文字。
- 六种植物各三阶段：种子/幼苗/成熟。苔藓等按自身形态变化，不强制所有植物开花。不因情绪低落、缺席或跳过任务枯萎。
- 播种动画约 1.5 秒；保存成功才播放，失败保留输入。支持减少动效、键盘操作和触摸，动画不会阻塞求助入口。
- 连续 3/7 天的晨露/蝴蝶作为装饰奖励；解锁后保留，不惩罚中断。用不同日期计数，防止一天反复记录刷奖励。

### CBT 自助练习

不能把“共情—反问—建议”直接等同完整 CBT，也不能把所有放松练习标成 CBT。

最小结构：发生了什么 → 脑中闪过什么想法 → 产生何种情绪及强度 → 可选查看支持/不支持该想法的线索 → 尝试更平衡的表述 → 一个微行动 → 后续感受。

使用渐进展开，每次一个问题，允许跳过，不强制种完植物立即回答。流程为保存播种 → 返回花园并展示新植物 → 非阻断邀请“愿意再看看这份感受吗”。

引导语示例：

- 焦虑：“刚才脑中最担心出现的情况是什么？如果愿意，我们可以一起看看它有哪些依据。”
- 低落：“这件事发生后，你怎样看待自己？现在有哪件小事，是你愿意尝试的？”
- 愤怒：“你当时最在意的需要或界限是什么？”

避免先质疑用户“真的一定会发生吗”、强行积极重构、要求罗列多个最坏结果或默认“你已做到最好”。

活动库每条必须含：适用场景、具体步骤、真实时长、方法类别、来源、适用边界及审核状态。认知练习、行为激活、放松/正念分开标注。来源只能支撑该练习，不能据此宣称整个应用有疗效。

呼吸入口默认提供舒适节奏、无强制屏息的练习；4-7-8 可作为可选模式，允许暂停、退出、改为自然呼吸，并提示不舒服就停止。未核实来源前不将 4-7-8 宣称为 CBT 核心技术或保证改善焦虑。

首版 15 条校园行动均控制在 1–5 分钟、可替换、可跳过，至少包括无消费和适合行动受限用户的选项。“图书馆坐半小时”“操场两圈”不标作五分钟任务；不把购买饮品设为默认解决方案。

### 复盘与报告

- 次日按用户所在时区显示轻提醒，可延后、关闭；不反复弹窗。多个待复盘植物合并呈现。
- 复盘允许好一些、差不多、更难受、暂不评价；记录后续强度与原强度对比，不强迫正向结果。
- 首版完成周报告：植物分布 + 真实数量/占比 + 行动数 + 复盘摘要。装饰密度不能替代可读数据。
- 六种情绪是分类，不直接排成“好坏分数”曲线。迷你曲线展示用户自评强度，并注明是个人记录。
- 数据稀疏时展示不足说明；“周中焦虑较多”须由时间分布支持，不能擅自推断“学业导致”。
- 花园成长值可作奖励，但保留连续记录天数和完成行动数的直白标签；它们不代表心理健康程度。

### 树屋与隐私

- 开场建议：“我是守园精灵知知。愿意的话，可以从今天的一件小事说起。” 不承诺“这里只有我们两个人”或绝对保密。
- 保留四个校园场景入口与快捷情绪按钮。普通回复简短，一轮一个主要问题；用户选择跳过认知练习时尊重其选择。危机求助不受三句话限制。
- 上下文仅由服务端按当前会话身份读取，默认不自动把最近三天敏感日记交给外部模型；经用户同意后使用，并可关闭。未完成与已完成任务状态须准确，不编造记忆。
- 用结构化输出表达 reply、阶段、风险路径、activityIds；服务端校验活动来自已审查目录，不能直接执行模型生成的任务或权限操作。
- “加入任务簿”必须用户点击，并防重复；关联植物和来源对话。
- 高风险提示优先于养成、摘记和普通任务；规则只是基线，必须测试否定表达、引用、第三人称、多轮升级、模糊表述和服务异常。求助资源需核验，模拟资源必须明确标注，不能假装已通知真人。
- 悄悄话模式第一版若实现：仅对新会话启用，本应用不持久保存正文，结束时清理内存，默认不带历史花园上下文，不自动生成可保存摘记。所有服务及日志均需遵守。
- 使用云端模型仍会传输消息，供应商是否留存取决于实际服务政策。上线前明确说明，不能写“不上传云端”或“走出树屋彻底消失”。已有持久化历史的删除是独立操作。
- 摘记改为显式“结束并生成摘记”，由用户预览后保存；不依赖页面退出或十分钟超时调用。

## 5. 技术任务与依赖

沿用 React + TypeScript、Spring Boot、FastAPI。已有 PostgreSQL/JDBC 是计划的持久化路线；内存模式仅用于开发。第一天确认本机数据库可用性，避免最后两天才发现部署依赖问题。

建议新增 Flyway V2，保留 V1 和旧 checkins 表：

| 对象 | 最小字段/关系 |
|---|---|
| emotion_entries | user_id、plant_type、emotion_type、intensity、trigger_text、created_at、用户时区/本地日期、幂等键；一日多条 |
| thought_records | entry_id、automatic_thought、evidence_for/against、balanced_thought、updated_at；各项可选 |
| activities | 扩展现有表的时长、步骤、方法类别、来源、边界、审核版本 |
| tasks | 扩展 entry_id、activity_id、来源对话、反馈；完成事件决定生长 |
| reflections | entry_id、复盘日期、后续强度、变化选择、备注；避免重复复盘 |
| garden_unlocks | user_id、效果类型、解锁时间；保留已解锁装饰 |

植物类型和情绪类别分开保存；生长不由情绪好坏决定。暂不把旧 1–5 心情分数硬映射成六种植物，旧数据作为历史记录展示。

API 责任示例：POST /api/garden/entries、GET /api/garden、GET/DELETE /api/garden/entries/{id}、PUT /api/garden/entries/{id}/thought-record、POST /api/garden/entries/{id}/reflections、GET /api/garden/reports?period=week；任务沿用既有接口并扩展。所有对象访问由服务端校验所属用户。

依赖顺序：会话与数据契约 → 播种/回看 → 日记与行动 → 生长/复盘 → 报告；聊天读取同一套数据。服务端实际确认持久化之后，前端才显示成功和生长。

## 7. 验证与材料

必须验证：保存/重复提交/失败恢复；用户 A 无法读改 B 的植物、任务、对话；重启仍有数据；删除后不再进入报告和 AI 上下文；重复完成不重复成长；零点和跨日复盘；空数据/跨周数据；模型超时、无效结构、缺少密钥；风险表达和误报；悄悄话正文不进入本应用持久层；键盘、手机、减少动效。

测试目标：整理约 30–50 个离线用例，覆盖普通困扰、认知引导、风险表述、边界要求与故障。用例集是工程验证，不是临床验证；报告原始数量、漏检和误报，不只给漂亮百分比。

争取 5–8 名自愿参与者做非敏感场景可用性试用，可用合成故事，记录任务完成情况、卡住的位置、对隐私说明的理解、访谈反馈。单人有限样本不用于声称“改善心理健康”或“疗效显著”。

主演示故事：考试前担心失败 → 种含羞草 → 记录“考不好就代表我不行”的想法 → 自主写出更平衡的理解 → 选择两分钟练习 → 任务完成、植物长叶 → 次日记录感受 → 周报告回看。另录求助与断网降级短片。跨日/多日场景用明确标注的合成历史数据，不假装真实使用七天。

材料沿用同一角色和花园意象：作品说明、演示视频、交互流程图、系统架构图、角色/植物设定、内容来源、测试与用户反馈、团队原创贡献、第三方组件/素材/AI 辅助使用说明。时长和文件规格按正式指南确定。

## 8. reverse-skill 与参考设计

已检索本机 skills 和 plugins 目录中的技能文件、名称及相关关键词，未找到已安装的 reverse-skill/Reverse Engineer Anything。用户补充 REA 后，已通过 GitHub API 核实官方项目为 [morluto/rea](https://github.com/morluto/rea)，官方技能路径为 [.agents/skills/reverse-engineer-anything/SKILL.md](https://github.com/morluto/rea/blob/main/.agents/skills/reverse-engineer-anything/SKILL.md)，npm 包名为 rea-agents，仓库标注 MIT 许可。
