# 知愈校园开发文档

## 1. 项目概述

### 1.1 项目名称

知愈校园心理健康支持系统

### 1.2 项目定位

知愈校园是一款面向大学生的非诊断型心理健康支持工具。系统通过情绪状态记录、AI 支持性对话、风险分层、活动推荐和任务反馈，帮助用户完成从“表达状态”到“采取行动”的心理健康管理闭环。

系统不能替代心理咨询师、精神科医生或紧急救援服务，不提供心理疾病诊断、药物调整和治疗结论。

### 1.3 首期目标

首期只实现以下四个核心模块：

1. 情绪与状态记录
2. AI 心理支持对话
3. 风险分层与求助引导
4. 情绪改善活动推荐与任务闭环

身体疾病问答、生殖健康、复杂多病关联分析和大规模社交功能不纳入首期开发范围。

### 1.4 核心业务闭环

```text
状态记录 -> AI 支持 -> 风险识别 -> 活动推荐 -> 加入任务 -> 完成反馈 -> 趋势更新
```

## 2. 产品范围

### 2.1 目标用户

- 在校大学生
- 面临学业、人际、就业、家庭或生活压力的用户
- 希望匿名获得基础心理支持，但暂时不愿直接线下求助的用户

### 2.2 用户场景

- 考试周焦虑、注意力下降
- 长期失眠、作息紊乱
- 情绪低落、孤独或缺乏动力
- 人际关系冲突后的情绪调节
- 希望记录情绪并建立规律习惯
- 出现较高风险表达，需要快速获得专业求助信息

### 2.3 首期不做的功能

- 心理疾病诊断
- 药物推荐或调整
- 自动替代人工心理咨询
- 对用户进行强制监控
- 公开用户情绪和测评数据
- 仅依靠大模型完成危机判断

## 4. 功能设计

## 4.1 情绪与状态记录

### 功能说明

用户每天可以记录心情、压力、睡眠和精力，并补充一段文字。记录结果用于趋势分析和活动推荐，不用于单独诊断。

### 页面

- 首页状态卡片
- 每日记录页
- 历史记录页
- 周趋势页

### 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| moodScore | integer | 心情评分，1-5 |
| stressScore | integer | 压力评分，1-5 |
| sleepHours | decimal | 睡眠时长 |
| sleepQuality | integer | 睡眠质量，1-5 |
| energyScore | integer | 精力评分，1-5 |
| note | string | 用户补充描述，可为空 |
| recordDate | date | 记录日期 |

### 规则

- 同一用户同一天默认只能有一条主记录，可编辑覆盖。
- 评分必须在限定范围内。
- 用户可以删除自己的记录。
- 删除后不得继续用于个性化推荐。

## 4.2 AI 心理支持对话

### 功能说明

提供支持性、非诊断型对话，重点是理解情绪、澄清需求、给出一个可执行的小行动，并在需要时引导专业求助。

### 对话流程

```text
提交消息
  -> Spring Boot 鉴权和保存消息
  -> Python 服务脱敏
  -> 风险识别
  -> 意图识别
  -> 知识库检索
  -> 大模型生成结构化结果
  -> 安全规则复核
  -> Spring Boot 保存并返回
```

### 回复要求

- 先回应用户感受，再给建议。
- 建议数量控制在 1-3 个。
- 每条建议尽量具体、低门槛、可执行。
- 不使用“你患有”“你一定是”等诊断性表达。
- 不承诺“我能保证你会好起来”。
- 高风险时停止普通活动推荐，优先展示求助流程。

## 4.3 风险分层与求助引导

### 风险等级

| 等级 | 典型表现 | 系统行为 |
|---|---|---|
| L0 | 普通烦恼、轻度压力、一般情绪波动 | 正常支持性回答和活动推荐 |
| L1 | 持续焦虑、明显低落、失眠，但无自伤表达 | 支持性回答，建议记录和联系可信任的人 |
| L2 | “不想活了”“活着没意义”等被动死亡或模糊自伤表达 | 进行安全澄清，展示专业求助资源，建议尽快联系他人 |
| L3 | 明确计划、时间、工具，或正在实施自伤/伤人行为 | 停止普通对话，展示紧急资源，触发人工升级流程 |

### 判断机制

首期采用三层组合方式：

1. 关键词和规则检测，保证高风险词快速命中。
2. 文本分类模型识别语义和上下文。
3. 大模型负责解释和生成支持性回应，但不能单独决定最终风险等级。

最终风险等级取规则、分类模型和上下文分析中的最高可信风险结果，并保留判断依据。

### L2 澄清问题

系统需要简短询问：

- 你现在是否有伤害自己的想法？
- 你是否已经想过具体的方式或时间？
- 你现在身边是否有可以陪伴你的人？

不要连续追问细节，不要求用户描述可能造成伤害的具体方式。

### L3 处理

- 明确提示当前情况需要立即获得现实中的帮助。
- 展示学校心理中心、校医院、当地急救电话等资源。
- 提供联系可信任的人和前往安全地点的建议。
- 记录风险事件和处理结果，不公开给普通用户。
- 比赛演示使用模拟资源和合成数据，不连接真实人工值班系统。

## 4.4 情绪活动推荐与任务闭环

### 活动分类

- 呼吸和放松：3 分钟呼吸、渐进式放松、正念练习
- 轻运动：散步 15 分钟、拉伸、晒太阳
- 自我关怀：情绪日记、记录三件小事、睡前减屏
- 社交支持：联系朋友、给家人打电话、参加低门槛活动
- 专业求助：预约心理中心、查看求助资源

### 推荐输入

- 当前心情和压力
- 最近睡眠和精力
- 对话识别出的情绪和意图
- 历史完成情况
- 用户活动偏好
- 当前风险等级

### 推荐原则

- L0/L1 推荐 1-3 个低门槛活动。
- L2 优先推荐联系他人和专业资源，不只推荐自助活动。
- L3 不推荐普通自助任务，直接进入危机求助流程。
- 用户可以拒绝、替换或删除推荐任务。

### 任务状态

```text
待开始 -> 进行中 -> 已完成
             \-> 已跳过
```

每次完成任务后记录完成时间、主观帮助度和可选反馈。

## 6. 数据库设计

### 6.1 核心表

#### users

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| username | varchar | 账号，可为空 |
| nickname | varchar | 昵称 |
| anonymous | boolean | 是否匿名 |
| role | varchar | USER 或 ADMIN |
| status | varchar | ACTIVE 或 DISABLED |
| created_at | timestamp | 创建时间 |

#### privacy_consents

记录用户同意的隐私政策版本、时间和撤回状态。

#### checkins

存储每日心情、压力、睡眠、精力和文字记录。

#### conversations

存储会话标题、风险最高等级、开始时间和结束时间。

#### messages

存储角色、原始消息脱敏副本、风险等级、AI 来源和创建时间。原始高敏感文本应尽量减少保存。

#### risk_events

存储风险等级、触发来源、处理动作、人工处理状态和审计信息。

#### activities

存储活动名称、分类、时长、适用风险等级、内容和审核状态。

#### tasks

存储用户任务、来源、计划时间、完成状态和反馈。

#### reminders

存储提醒时间、重复规则、是否启用和最近执行时间。

#### knowledge_documents

存储知识条目、来源、审核人、版本、标签和向量索引。

#### campus_resources

存储心理中心、校医院、热线和紧急资源，支持后台修改。

#### audit_logs

记录管理员操作、风险事件处理、数据导出和删除等敏感行为。

### 6.2 数据安全要求

- 敏感字段最小化保存。
- 传给模型前进行手机号、邮箱、身份证号等脱敏。
- 生产环境使用 HTTPS 和数据库加密存储。
- 日志中禁止输出完整心理对话内容。
- 用户可以导出和删除自己的记录。
- 测试阶段只使用合成数据或获得明确授权的匿名数据。

## 8. AI 与知识库实现

### 8.1 RAG 流程

```text
用户问题
 -> 脱敏
 -> 意图识别
 -> 查询改写
 -> pgvector 相似度检索
 -> 标签和风险等级过滤
 -> 拼接审核内容
 -> 大模型生成
 -> 输出格式校验
 -> 安全规则复核
```

### 8.2 知识库内容要求

- 内容必须有来源和审核日期。
- 每条内容标注适用人群、风险等级和禁用场景。
- 不使用未经审核的网络帖子作为核心知识。
- 保留文档版本，支持重新生成向量。
- 回答尽可能返回来源标题，方便追踪。

### 8.3 提示词约束

系统提示词必须包含：

- 角色是心理健康支持助手，不是医生。
- 禁止诊断、保证和药物指导。
- 先回应情绪，再给少量行动建议。
- 高风险时优先求助，不继续普通闲聊。
- 不要求用户提供伤害自己的具体方式。
- 如果知识库没有可靠依据，应明确说明不确定并建议咨询专业人员。

- 用户数据删除测试
- 管理员越权测试

### 11.2 AI 测试

建立包含以下类型的合成测试集：

- 普通压力表达
- 失眠和焦虑表达
- 模糊的死亡表达
- 明确自伤风险表达
- 与心理无关的问题
- 诱导模型诊断的问题
- 要求模型提供危险方法的问题

记录以下指标：

- 风险识别召回率
- 风险识别精确率
- L2/L3 漏检率
- 普通用户误报率
- 回答响应时间
- 回答是否出现诊断性表述
- 回答是否给出可执行建议

### 11.3 验收标准

- 核心页面可以在移动端正常使用。
- 普通对话、活动推荐和任务闭环完整可演示。
- 高风险场景能进入求助流程。
- AI 服务不可用时，系统可以返回安全的降级提示。
- 敏感内容不会写入普通应用日志。
- 用户可以删除自己的记录。
- 系统可以通过 Docker 部署。

## 14. 推荐的首个可运行版本

第一个可运行版本只要求完成以下流程：

```text
匿名进入
 -> 完成今日情绪记录
 -> 输入“最近压力很大”
 -> AI 返回支持性回答
 -> 推荐 3 分钟呼吸练习
 -> 加入今晚任务
 -> 标记完成
 -> 查看情绪趋势
```

完成这条流程后，再扩展风险分层、求助引导和论文实验。这样可以尽早获得可演示成果，同时避免项目在早期被复杂功能拖慢。
