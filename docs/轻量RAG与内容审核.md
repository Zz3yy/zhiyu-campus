# 考试压力知识库、混合检索与 Agentic RAG

## 内容与来源

运行时从 `zhiyu-server/src/main/resources/knowledge/corpus.json` 加载 **150 个文本块**：19 条原行动、45 条原理/边界说明、43 条校园案例、43 条引导模板。43 个新增主题各有不同正文的概念、案例与模板，另外保留原 2 条引导。涉及执行意图、灾难化预测、自我关怀、提取练习、间隔重复、交错练习、粗糙初稿、同伴比较、宿舍噪声与备考等。

这是**原创中文草稿知识库**，并非导入的临床语料，也不是 150 项已经验证有效的干预。没有复制付费书籍段落、论文摘要或私人咨询对话。2026-10-29 检索 GitHub 的三个候选项目未显示明确许可，因此未导入；不能用公开可见代替可复用授权。`sources.json` 登记实际核验程度：三篇论文完成 Crossref DOI/题名核对，NHS 原文入口及思维记录结构已核对，WHO 出版物入口可访问；这些工程检查不等于人工内容审核。

**生产审核文件 `reviews.json` 仍为空，150 条均待人工审阅。** 待审内容不会进入模型生成上下文；旧行动可作为带草稿来源的本地建议。系统不会把扩充数据、通过测试或模型署名当作人工批准。

每条 JSON 有 `id/activityId/title/content/category/version/source/boundary`，以及 `sourceId/sourceLocator/sourceRelation`。来源关系区分“理论参考”和“项目自拟场景”，不暗示 NHS/WHO 验证过校园案例；最坏/最好/最可能的三栏是项目改写，不冒充 NHS 原文七步。

元数据字段（Java 风格 camelCase，与用户需求字段语义一致）：

| 字段 | 含义 |
| --- | --- |
| `metadata.timeMinutes` | 1–60 分钟的阅读/讨论或行动预算；本库使用 1、2、3、5 分钟；并非整个学习方法需要的总时间 |
| `metadata.targetEmotions` | `anxiety / procrastination / frustration / confusion`，是内容适用标签，不是用户诊断 |
| `metadata.cognitiveLoad` | `very_low / low / medium`，项目暂定负担分级，需人工核对 |
| `metadata.scenes` | `dormitory / library / classroom / commute` |
| `metadata.keywords` | 条目主题关键词；没有悄悄连接用户私人资料 |

## 检索实现

1. 校验会话与风险；紧急危险直接固定求助，先于检索和云端调用。云端、花园资料、行动反馈仍分别授权。
2. 从用户主动输入提取明确时间/场景条件；“太难、不想看”等反馈约束为极低负荷。只读用户消息，忽略助手建议作为个人事实。当前解析是有限表达规则，复杂否定、引述与模糊时长仍需澄清，不宣称完美理解。
3. 先按审核指纹、允许的行动 ID、时间、情绪、场景、负荷过滤。pgvector 查询带参数化 `WHERE time_minutes <= ?`、数组包含条件与负荷上限；数据库和内存两条路径均执行限制。
4. 中文使用字符二元组、英文使用词项计算 **Okapi BM25（k1=1.2、b=0.75）**；统计量基于本次合格小库，在 Java 计算。pgvector 返回 256 维词面哈希向量的余弦分数。
5. 两路排名通过 **RRF** 融合：`1/(60+BM25_rank) + 1/(60+vector_rank)`，每次取最多 3 条。无真实词项交集的结果被排除，避免单凭哈希碰撞形成命中。没有再使用旧版 0.12 余弦阈值。
6. 所有查询和查询向量只在本轮内存中使用，不写数据库；无额外云端 embedding 调用。

模式分别标为 `pgvector-hybrid` 和 `memory-hybrid`。这是**BM25 + 词面向量的混合检索**，不是神经语义检索；两路仍共享词面特征，不能宣称具备强同义改写召回。没有经过用户标注的相关性基准或医学效果评测。150 条用精确距离查询，不需要伪装成大规模 ANN 系统。

## Agent 动态检索

初始检索是本地预检，界面明确标为“初始检索”，不能算作模型自主调用。模型可主动调用：

```json
{
  "name": "search_knowledge_base",
  "arguments": {
    "query": "太难，想先降低复习启动的负担",
    "emotion": "frustration",
    "time_limit": 2,
    "scene": "dormitory",
    "cognitive_load": "very_low"
  }
}
```

只有 `query` 必填。其余是检索条件，不等于给用户写入画像；模型不能放宽用户明确时限/负荷，不能将已说明的宿舍改为图书馆。字段类型、枚举、长度、数量均在服务端校验。无结果可改写查询，每条用户消息最多 **3 次知识工具检索、7 次模型往返**，每次响应最多 8 个工具调用；总模型等待预算约 90 秒（单次请求仍最多 25 秒），前端 105 秒兜底。

推荐闭环是 `search_knowledge_base → search_activities → propose_action → 用户点击 → create_task`。知识检索命中不等于行动已被批准；行动工具单独检索允许目录中的已审核行动依据，以免概念条目挤掉行动卡的来源。仅用户确认接口可创建任务。

重新知识检索会替换当前证据、清空已搜索行动与旧提议。最终 `citationIds` 必须属于最后一次知识检索加后续行动依据检索；旧轮命中的 ID 不能继续授权新建议。这是有上限的工具驱动查询改写/再检索，**不是知识图谱多跳推理**。

用户主动询问“什么是执行意图”等时进入 `EXPLAIN`：必须实际检索并引用资料，不自动推荐或创建行动。普通澄清、休息仍遵守原流程。不通过增加 150 个任务来展示 RAG。

空库、无命中、数据库异常、预算耗尽、引用不匹配都显式降级。无依据时不编造认知练习。引用校验只证明 ID 来自当前证据，不能证明自然语言每句话忠实；仍需要人工评测。

## 可视化

“查看知识依据 (RAG)”折叠面板显示每次真实检索的类型、筛选条件、条目 ID、内容、来源关系、链接、审核人/日期，分别标注词面向量相似度、BM25、RRF。命中和最终引用分开。分数不是正确率、疗效概率，也不将 `memory-hybrid` 宣称为 pgvector。

`NO_APPROVED_CONTENT` 显示暂无审核内容；`NO_MATCH` 说明本轮条件无匹配；`UNAVAILABLE` 显示检索不可用。只有实际检索才有记录，没有联网或调用模型时不伪造工作流。

## 审核与维护

逐条审核入口见 [内容审核清单](内容审核清单.md)，机器可读队列为 [knowledge-review.json](knowledge-review.json)。

```sh
python scripts/knowledge-review.py
python scripts/knowledge-review.py --export
```

第二个命令重新生成全部“待审”的审核工作表，**会覆盖工作表中的手工勾选，请先保存审核记录**；它不改变生产 `reviews.json`。更改来源、元数据、正文、边界等都会改变 SHA-256 指纹；Java 与导出脚本使用同一字段顺序。

`GET /api/garden/chat/knowledge` 和 `/knowledge/review` 是登录匿名花园后的只读公共内容端点，后者包含运行时指纹。真正审阅后，仅将通过条目的 `id/contentHash/reviewer/reviewedAt` 记录放进 `knowledge/reviews.json`。署名必须来自实际审核人，日期有效且不晚于当天。不要把合成测试署名用于生产。重启后读取审核记录，首轮数据库检索同步；删除审核或改变指纹后条目不再合格。

`scripts/expand-knowledge.py` 是本次内容初稿的可复现编写脚本，**不是日常导入命令**；重新运行会覆盖 corpus，后续应以 JSON 为维护源。所有 150 条稿件以 JSON 正文为准。

## 数据库

保留 V3 原表，V4 增加元数据列及普通/GIN 索引，Flyway 增量迁移，不重写旧迁移。首次检索读取 JSON、生成本地向量并 upsert 公共知识；只从当前 corpus 且当前审核有效的条目检索，残留旧行不能混入。不会把用户对话、花园或设备数据导入知识库。

Compose 仍用 `pgvector/pgvector:pg16`。普通 PostgreSQL 必须先有 vector 扩展与迁移权限，失败返回真实不可用状态。内存模式无需数据库，但不能代替 pgvector 验收。

## 验收与演示边界

后端覆盖真实 PostgreSQL、元数据过滤、两路排序、未审核/过期指纹排除、再检索替换旧引用、工具预算、用户约束与安全暂停。浏览器测试检查来源状态、动态面板及移动端；其中命中面板使用明确标注的合成响应，不是生产模型实测。

只有实际人工审核内容后，才能演示真实豆包基于生产知识库的动态生成。建议先审核“执行意图/自我关怀/降低认知负担”相关概念与四个复习行动，再用真实模型验证查询、拒绝后的改写、来源追溯及用户确认。不能把测试环境的批准记录或固定响应用于冒充正式演示。
