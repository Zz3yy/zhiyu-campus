# 复习 Agent 闭环：实现范围与验收

日期：2026-10-23。本轮不修改豆包密钥、启动脚本、数据库结构或花园视觉。

前端遵循 frontend-design 的真实文案与现有样式复用原则，未重设色板、字体或植物插画。手机端因授权说明变长改为自然页面高度与独立消息滚动，避免底部控件裁切；系统偏好减少动态效果时不播放逐字动画。

## 实现边界

- 采用规则约束的混合 Agent，不是训练模型：豆包只生成自然语言理解回应，`StudyAgentPolicy` 决定阶段与一个目录行动，服务端追加问题或行动说明。
- 第一轮澄清复习卡点；后续结合最近表达和显式时间意愿选择一个行动。用户表示暂不安排时暂停建议，不自动创建任务。
- 四个复习行动：只打开资料（1 分钟）、看目录选小节（1 分钟）、读一段（2 分钟）、读熟悉题题干（3 分钟）。这是自拟的步骤层级，不代表经过验证的心理难度或疗效。
- 推荐与任务保存分离。只有用户点击加入任务才写入；同一植物/无关联植物的同一行动，TODO 防重复；DONE/SKIPPED 后可主动再添加。原任务与反馈保留，重复完成同一任务不会重复成长。

## 反馈如何改变建议

只参考当前匿名花园近七天、最多 8 条目录复习行动；忽略自由标题任务、无效时间、未完成任务及其他用户。相同动作以最近一次反馈为准。

| 反馈 | 行为 |
| --- | --- |
| 太难 | 减少步骤；最小行动仍太难时不重复强推，转为澄清或暂停 |
| 没有帮助 / 帮助评分 1–2 | 避开近期该行动，改选可行的另一项；无候选时继续询问 |
| 普通跳过 | 第一轮询问偏好，不推断原因；再给出建议时避开刚跳过的行动 |
| 完成、未评分 | 保持小步骤，不声称有效，不自动加量 |
| 完成、评分 3 | 保持小步骤，明确中等评分不等于效果证明 |
| 完成、评分 4–5 | 可再次选择同样小步骤，仍需用户确认，不自动加量 |

## 授权与安全

- “使用豆包”仅授权本次消息与最多 12 条本次对话；花园资料、行动反馈各自另行授权，默认关闭。
- 行动反馈授权仅发送目录 ID、状态、评分和难度字段，不发送笔记、自由标题、任务 ID 或时间戳。未授权时也不会用历史反馈生成随后外发给模型的计划，避免间接泄露。
- 本地规则引导使用近期反馈但不外发。云端调用失败时沿用本轮已经授权的资料范围，不擅自扩大读取后发送。
- 切换授权清空本页对话和输入；离开树屋也会清空。关闭授权无法撤回供应商已收到的数据。
- 风险规则在模型调用之前执行；模型 needHelp=true 时只显示固定求助内容。求助分支清空推荐、隐藏本页旧建议按钮并禁用本次普通聊天，保留主动求助入口。不通知任何第三方。
- 模型 phase/行动不符、无效 JSON、非复习行动、多行动、部分越界表述或供应商故障：明确显示本地降级，并提示内容可能已外发。
- 规则和基础文本检查存在漏报与误报，不能保证识别所有风险或阻止所有越界措辞，不替代现实支持。

## 手动验收

1. 在 VS Code 后端终端手动重启本项目后端，让新代码生效；沿用已确认的豆包启动方式。前端保持原来的 5173 地址并刷新，不切换主机名。不要分享 API Key。
2. 进入树屋，勾选“使用豆包”和“允许使用近期行动反馈”，花园资料可以不勾选。
3. 发送合成内容“复习资料太多”，应先问卡点、不出现加入按钮；回复“不知道从哪里开始”，应出现一个目录小行动和理由。检查每条消息来源；“已配置”不等于调用成功。
4. 点击加入后到任务簿标记“太难”。重新进树屋并重新授权，重复两轮对话，应减少步骤；不是自动写入新任务。
5. 将新的行动完成并给 5 分；重新进树屋，应允许建议同样步骤，并可主动再添加；同一条 TODO 连续点击不会增加重复任务。
6. 将行动标记无帮助或低分，下一次避免原样重复；普通跳过不推断动机。“想先休息”不提供行动。
7. 关闭反馈授权，对话清空；新模型请求不得带历史反馈。关闭云端则使用本地引导。
8. 仅用合成危险表达检查固定求助与旧推荐按钮消失，确认没有自动创建任务或联系真人。

## 2026-10-26 工具调用升级

本轮把复习 Agent 从“单次结构化回复”升级为方舟兼容的 Function Calling 工作流。模型可在一次会话中依次调用：

- `query_garden_state`：仅读取用户单独授权的近期花园资料或行动反馈，返回最小匿名字段；
- `search_activities`：在服务端审核目录中检索最多三个复习启动候选；
- `propose_action`：提出一个候选及理由，不产生任务副作用；
- `create_task`：在模型侧始终返回 `requires_user_confirmation`，用户点击行动卡片后才调用专用确认接口写入任务。

每次工具调用都由服务端执行并记录为本轮 `toolTrace`，前端显示工作流轨迹，便于演示和审计。服务端仍校验风险、授权范围、候选目录、阶段和单行动约束；工具调用失败或模型返回不合规内容时，沿用本地规则引导。该实现使用 OpenAI 兼容的 Function Calling 请求格式，不将其描述为 MCP Server。

本轮自动验证：后端 **50 项测试通过**（新增工具调用多轮协议、授权查询隔离、确认令牌幂等和植物关联绑定测试）；前端 TypeScript 检查与生产构建通过。真实豆包是否返回工具调用取决于所选方舟模型的工具调用能力，需在已配置的本地服务中检查每条回复的 `toolTrace`；没有工具轨迹时仍可安全降级到本地规则流程。
