# 知愈校园工程化开发流程

## 迭代节奏

1. 明确改动范围、理由、用户流程和验收标准，确认后实现。
2. 按需设计接口、数据结构与数据库迁移。
3. 完成实现，运行与改动相关的测试和构建。
4. 更新文档，提交一个可说明、可回退的完整改动。
5. 推送并核对远端提交；团队协作时通过 Pull Request 评审合并。

## 分支与提交

`main` 保留可演示版本。新功能使用 `feature/*`，修复使用 `fix/*`，仓库维护使用 `chore/*`；当前不强制增加 develop 分支。分支只在实际使用时创建。

```sh
git switch main
git pull --ff-only origin main
git switch -c feature/your-feature
# 完成实现与验证后，逐项暂存相关文件
git add path/to/changed-file
git diff --cached --stat
git commit -m "feat: 描述本次新增能力"
git push -u origin feature/your-feature
```

提交类型使用 `feat`、`fix`、`test`、`docs`、`chore`；说明真实改动，不为了数量拆分空提交。基线提交以前的开发未被 Git 记录，不回填日期或伪造历史。不对已共享的 main 强制推送。

真实 `.env`、依赖、构建产物和测试输出不进入提交。检查待提交文件名与忽略规则，不读取或输出开发者真实模型凭证。作者名称和邮箱属于公开提交元数据。

## 验收要求

- 前端：生产构建；涉及交互时，在独立内存后端上运行对应 Playwright 验收。
- 后端：Spring Boot 测试；涉及数据库变更时，单独验证迁移和持久化。
- FastAPI：涉及该服务时运行 pytest；当前主流程不依赖此服务。
- Agent：核验用户确认建任务、工具参数及授权边界、风险暂停、清晰降级；模拟测试不替代真实模型评测。
- 文档与配置：核验相对链接、命令、环境变量说明，必要时在独立克隆中验证。

常用命令见 [README](../README.md)，本次仓库验证证据见 [规范化验收记录](仓库规范化验收-2026-10-27.md)。每次记录实际执行结果与未覆盖范围，不把旧结果冒充本次验证。
