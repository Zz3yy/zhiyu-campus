## 验证覆盖

- 实际 `pgvector/pgvector:pg16`（PostgreSQL 16.15）临时容器，127.0.0.1:55439；Flyway V1–V4 执行成功，重复 migrate 无待迁移，150 条向量维数为 256。
- pgvector 与内存混合排序的同查询/过滤结果一致；修改数据库中测试条目的时间后，SQL WHERE 将其排除，证明不是仅在内存筛选。
- 未审核、过期内容指纹、撤销审核、数据库异常不进入生成证据。
- BM25/RRF 分数随真实检索返回；无真实词项重叠时，不靠哈希碰撞伪造命中。
- 用户“宿舍、两分钟”条件跨轮保留；助手文字不能成为用户事实；模型要求五分钟/更高负荷时不能放宽明确限制。
- 用户拒绝“读一段”后，极低负荷再检索及更轻起点可经过模拟工具链返回；没有自动创建任务。
- 两次知识检索后旧引用被拒绝；新引用可用于 EXPLAIN，不创建行动；检索预算耗尽会降级。
- 自伤表达先进入固定求助，未调用检索或模型；模型直接 `create_task` 仍拒绝。
- 来源面板区分命中与引用、词面向量/BM25/RRF、内存与 pgvector、待审核和已审核。

## 复现

先准备一次性、无用户数据的 PostgreSQL/pgvector 测试库，绝不把测试变量指向项目数据库：

```powershell
. .\scripts\env-d.ps1 # 可选，仅维护者本机 D 盘工具链
$env:ZHIYU_PGVECTOR_TEST_URL='jdbc:postgresql://127.0.0.1:55439/postgres'
mvn -f zhiyu-server/pom.xml -B -o test
pnpm --dir zhiyu-web build
python scripts/knowledge-review.py
```

未设测试数据库变量时，真实数据库测试会跳过，不能宣称该次完整数据库验证通过。库内合成审核人仅用于测试，不改变生产资源文件。数据库测试会写入/修改测试库知识表。

干净内存后端与前端分别启动后：

```powershell
$env:E2E_API_BASE_URL='http://127.0.0.1:18080'
$env:E2E_BASE_URL='http://127.0.0.1:5174'
pnpm --dir zhiyu-web test:e2e
```
